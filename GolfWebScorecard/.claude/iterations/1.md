## Key Decisions
1. **localStorage is mandatory** — Pure JS memory is not acceptable for data entry. Data must survive page refresh. Key: `ezygolfer_recovery_rounds`. Called from every mutation function.
2. **Export format mirrors EzyGolfer backup exactly** — `{ courses: [], rounds: [{ id, courseName, teeName, date, isComplete, totalScore, scoreEntries: [{holeNumber, strokes, putts, fir, gir, penalties}] }] }`. Import via EzyGolfer Settings → Import Backup works directly.
3. **Confirmation dialog for Clear** — Destructive action; `confirm()` required before clearing.
4. **Divider at `i === 9`** — 0-indexed array: `i === 9` puts left border on hole 10's cell (visually after hole 9). `i === 8` was wrong (appeared between holes 8 and 9).

## Problems Encountered
1. **Scorecard divider in wrong place (between 8/9 instead of 9/10)**
   - Root cause: 0-indexed array; `i === 8` targets the 9th element (hole 9's cell left border)
   - Fix: `i === 9` in all 3 occurrences in `renderRounds()`

2. **Data lost on page refresh**
   - Root cause: rounds array was pure JS memory — no persistence
   - Fix: `saveRounds()` calls `localStorage.setItem('ezygolfer_recovery_rounds', JSON.stringify(rounds))` on every mutation; `loadRounds()` called at boot

3. **Add Round button at top required scrolling back after each add**
   - Fix: Moved to bottom of section, next to Export button

## Decisions & Learnings
- EzyGolfer backup JSON format: `{ courses: [], rounds: [{ id, courseName, teeName, date, isComplete, totalScore, scoreEntries: [{holeNumber, strokes, putts, fir, gir, penalties}] }] }`
- `date` field must be ISO8601 with fractional seconds: `new Date(dateStr + 'T00:00:00.000Z').toISOString()`
- `isComplete: true` required for EzyGolfer to count the round in handicap calculations
- `totalScore` = sum of all 18 hole strokes
- localStorage `setItem` is synchronous — no async needed
- Any stateful web tool that involves data entry MUST persist to localStorage immediately on every change
